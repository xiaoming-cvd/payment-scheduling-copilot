## 一、一句话定位

面向大企业财务/司库团队的**供应商付款计划排程工具**：当临时加急发票到账、资金头寸吃紧等扰动发生时，AI 辅助生成"尽量少改已承诺付款安排"的调整草案，人工逐项确认后锁定执行，三种求解方法对比、独立校验兜底、决策过程全程可回放。

> 对中兴新云而言：这不是一个陌生场景——"供应商智能结算系统"中已包含**付款排程**功能，司库数智化是其四大产品支柱之一。本作品相当于为这一既有业务场景提供"AI + 运筹优化"的智能化增强，评委有天然的业务手感。

## 二、业务痛点与证据

### 2.1 场景还原

大型企业每月集中处理数百至数千张供应商发票。付款计划排程要同时满足：

- **资金约束**：账上可用资金/授信额度有限，不能全部到期即付；
- **合同约束**：付款账期（如月结 60 天）是合同承诺，随意改动损害供应商关系；
- **优先级差异**：战略供应商、加急单、违约罚息高的订单不能随意后延；
- **扰动高频**：临时加急发票、退货红冲、资金到账延迟，随时打乱原计划。

### 2.2 现有做法的不足

现有做法是财务在 Excel 里手工调整：凭经验决定谁先付谁后付。问题是——

1. **改动无依据**：每一处延期/提前为什么这样排，说不清，审计和总办会上讲不出理由；
2. **顾此失彼**：优先保供应商关系就可能资金利用率低，保资金就可能违约，手工权衡没有量化；
3. **改动不可控**：调一单牵动全局，已经通知供应商的付款日被连环改动，引发投诉；
4. **无校验**：排完没人能独立验证"到底超没超额度、破没破合同账期"。

### 2.3 频率证据（回应"低频质疑"）

与预算调整不同，付款排程是**月/周甚至日频**的常规动作；中兴新云自己的供应商结算产品即内含付款排程模块，说明这是其客户的高频刚需场景。（证据来源见附录 A）

## 三、方案增量：我们新增了什么能力

| 维度 | 现有业务做法 | 本作品新增 |
|---|---|---|
| 排程方式 | Excel 手工排 | AI 读懂自然语言调整意图，出草案供人工确认 |
| 改动控制 | 改多少凭感觉 | **低扰动目标显式化**：承诺付款日改动次数/幅度最小，设成本上限（如总资金成本 ≤ 1.10 × 参考方案） |
| 方案质量 | 单一手工方案 | **三方法对比**：插入式（只排新单）/ 低扰动（少改已承诺）/ 完全重排（质量上限最高），同预算同口径对比 |
| 结果可信 | 采信求解器自报 | **独立校验器**：用原始合同与资金数据把付款计划逐笔重新推演，不采信任何求解器自报标志 |
| 决策透明 | 黑箱 | **决策过程白盒回放**：大白话结论 + 专业明细（拒绝原因计数、候选对比表）+ 原始诊断 JSON 三层展示，全部来自真实运行记录 |
| 用户体验 | 专业表格 | **小白版 / 专业版双模式**：不懂财务的人也能看懂"钱为什么这样排" |

**一句话价值主张**：把"付款计划怎么改"从一个依赖个人经验的黑箱决策，变成**有依据、可解释、可审计、改动可控**的科学决策。这与大赛"流程合规透明、交付稳定及时"的方向目标直接对应。

## 四、技术方案概要

### 4.1 运筹模型（对应上个项目的映射）

| 上个项目（城配调度） | 本题（付款排程） |
|---|---|
| 车辆路线 | 付款批次/计划 |
| 配送客户节点 | 待付发票/订单 |
| 车辆容量 | 资金池可用额度（按日/按周） |
| 客户时间窗 | 合同账期/承诺付款日（可容忍延后天数） |
| 新插入订单 | 临时加急发票 |
| 行驶时间 | 资金占用成本/违约成本/提前付款折扣 |
| 低扰动（少换车少改序） | 少改已承诺付款日、少换批次 |

约束：资金平衡（每日付出现金 ≤ 可用额度）、账期合规、优先级规则、硬锁定（已通知供应商的付款日不可动，除非人工显式解锁）。

### 4.2 系统构成（复用上个项目架构）

- 自然语言 → 调整意图草案 → 人工逐项确认 → 场景版本锁定（与上个项目同一交互流）
- 三方法求解引擎：插入式 / 低扰动 / 完全重排（完全重排默认 OR-Tools，COPT 可选作小规模最优性验证）
- 独立校验器：逐笔重推演，校验资金约束、账期约束、锁定约束
- 决策回放面板 + 双模式前端
- 如实状态语义：无解 ≠ 不可行；超时 ≠ 证明不可行；找到可行解 ≠ 已证明最优
