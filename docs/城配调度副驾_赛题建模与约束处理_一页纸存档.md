# 上个项目存档一页纸：城配调度副驾

> 存档日期：2026-10-22 ｜ 用途：为"中兴新云杯"新选题（供应商付款排程）提供方法论底稿

## 一、赛题（要解决什么问题）

**业务场景**：城配企业每日出车前，调度员按已知订单排出车计划并下发司机。行驶途中临时加单（大客户急单、前置仓爆单）到来，需要把新单并入原计划，同时尽量少打扰已经通知司机的老计划。

**现有做法的三种局限**：① 人工电话改单——靠个人经验、响应以分钟计、无全约束自动核验，漏单/超时/超载风险高；② 全量重排——质量上限高但老计划面目全非，司机端混乱；③ 简单插单——改动最小但经常塞不进去。

**我们要做的**：AI 理解调度员的自然语言约束（如"o1 不能换车"）→ 出结构化草案 → 人工逐项确认 → 三种方法在同一输入、同一预算下求解 → 独立校验 → 白盒化解释结果。

## 二、建模思路（VRPTW 低扰动重排）

**模型底座**：带时间窗的车辆路径问题（VRPTW）。节点 = 仓库 + 客户点；边权 = 行驶时间矩阵；车辆有容量上限；每个客户有服务时长和可送达时段 `[最早, 最晚]`（时间窗约束作用于服务开始时刻）。

**三种方法（同输入、同预算、独立校验）**：

| 方法 | 思路 | 定位 |
|---|---|---|
| insert 插入式 | 枚举新单插入位置（队首/队尾/两旧任务间），不搬动旧任务 | 快速基线；紧约束下常快速无解 |
| low_disruption 低扰动 | 可行插单种子 + 单任务搬动/交换/局部修复生成候选池，按（换车数 → 相邻破坏数 → 成本）字典序选 | **产品主方法**：成本上限内最小化扰动 |
| rebuild 完全重排 | 全部订单重新优化（默认 OR-Tools，COPT 可选） | 质量基线 |

**成本上限链**：业务上限 = `1.10 × 参考成本`；参考成本优先级：跨方法已验证最低成本 → 原计划成本（容缺口径）→ 候选池最优（回退时醒目标注 `pool_fallback`）。上限内无候选则推荐池内最优但不计入达标可行率。

**扰动量化**：换车数（旧任务车辆归属变化计数）+ 相邻关系破坏数（同车顺序相邻被打断的计数，新单引起的索引移动不计）。

## 三、约束怎么处理（工程红线）

1. **可行性不采信求解器自报**：一律由独立校验器从输入矩阵重算——逐站推演到达/服务/离开/返回时刻、装载量、时间窗、锁定约束，复核通过才算可行。
2. **状态语义红线**：`TIMEOUT / NO_FEASIBLE_FOUND ≠ 不可行`（毫秒级返回只是算法快速没找到）；只有 COPT 对当前 MIP 模型报 `MIP_INFEASIBLE` 才可写"证明不可行"，且不得扩展为原始业务问题不可行；OR-Tools 找到可行解 ≠ 证明最优。
3. **硬约束 vs 偏好分层**：AI 草案区分硬约束与软偏好，附原文依据；指代不清返回澄清，不猜。
4. **人工确认门**：自然语言约束必须逐项人工确认才生效；锁定（不许换车的旧单）只能人工显式解锁。
5. **预算口径诚实**：三方法统一 60 秒端到端软预算，越界（最大 77.3s）单独成节披露，不宣传为严格同预算。
6. **数据纪律**：接口层统一整数秒、`time_origin` 必须带时区、容量维度单一且缺失不得填 0 冒充、矩阵中 0 是合法值不能判缺边。

## 四、验证结果（冻结评测，39 场景 = 23 dev + 16 test，Solomon + Kilby）

- dev 集低扰动可行率 **65%** vs insert/rebuild 各 **13%**；配对样本成本 5/5 更低。
- 8 个紧时间窗失败场景做了根因诊断（初解构造失败）+ 时间窗放宽敏感性实验（放宽后 8/8 可解）。
- 全程阶段审查留痕（0~7 阶段 + 三次复审），360 测试通过，README/视频/报告齐备。

## 五、可平移到新题（付款排程）的映射

路线 → 付款计划；客户节点 → 待付发票；车辆容量 → 资金池额度；时间窗 → 合同账期/承诺付款日；新加单 → 加急发票；低扰动 → 少改已承诺付款日；独立校验 → 逐笔重推资金/账期/锁定。内核同构，约七成工程资产可直接复用。
